Why does a function remember variables from a scope that has already finished executing? This lesson works through closures the way an interviewer would — starting from a bug you have almost certainly written.

You'll trace the scope chain by hand, build a counter factory, and finish by explaining — in one sentence — why closures make private state possible in JavaScript.
LESSON NOTES

A closure = a function + the lexical environment it was created in. Three things to remember:

1. Scope is decided where a function is written, not where it is called.  2. Each call creates a fresh environment.  3. Returned functions keep their environment alive.
